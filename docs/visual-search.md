# Visual Search — Vector Upgrade (Delta 1)

Match a photo against SmartBuy's own catalog by **vector similarity**,
not by keywords: a public image URL is captioned (BLIP), the caption
is embedded (all-MiniLM-L6-v2, 384 dims), and `match_products()` in
Supabase (pgvector) returns catalog products by cosine similarity.

**Status: dormant until the owner completes the steps below.** With
nothing configured, `POST /api/v1/visual-search` answers 503 and the
backfill route refuses — it never invents a match.

## What already exists

- `/scan` (Option 6) is unchanged: uploaded/captured photos NEVER
  leave the browser and are NEVER stored. That rule is absolute and
  this upgrade does not touch it.
- `POST /api/v1/scan` (SerpAPI Lens visual match) is unchanged.
- This upgrade only adds a second path: `POST /api/v1/visual-search`.

## Owner setup (3 steps)

### 1. Free Hugging Face account + token

1. Create a free account at https://huggingface.co (no card needed).
2. Create a token at https://huggingface.co/settings/tokens
   (type: **Read** is enough).
3. In Vercel → project `shahjahanaibuy-b1zp` → Settings →
   Environment Variables, add `HF_API_TOKEN` = the token
   (Production scope), then redeploy.
4. Free-tier note: the Inference API is rate-limited and models can
   take ~10–20s to load on first use (cold start). The route answers
   503 "model is still loading" in that case — retry, never a fake
   result.

### 2. Run the SQL in Supabase (once)

In the Supabase dashboard → SQL Editor, open
`supabase/add-visual-embeddings.sql`, press **Ctrl+A** (select all),
then **Run**. It:

- enables the `pgvector` extension (free on Supabase),
- creates `product_embeddings` (one 384-dim vector per product),
- creates `match_products(query_embedding, match_count)` — cosine
  similarity search, best first,
- ends with a verifying `SELECT` of the new table's columns.

Verify it worked: the last result should list `product_id`,
`embedding`, `updated_at`. If you see an error instead, do not
proceed — the routes will keep answering 503 until this runs.

### 3. Backfill the catalog (once, admin only)

Sign in as an admin and call once:

```bash
curl -X POST https://shahjahanaibuy-b1zp.vercel.app/api/v1/admin/visual-search-backfill \
  -H "Cookie: <your admin session cookie>" \
  -H "Content-Type: application/json" \
  -d '{}'
```

(or call it from any HTTP client while signed in as admin in the
browser). It embeds each product's name + brand + description and
upserts the vectors. The response reports
`{ total, alreadyEmbedded, embedded, failed }`.

- **Resumable:** without `force`, products that already have an
  embedding are skipped. If the call is cut short (free-tier
  function timeout), just call it again to finish the rest.
- **Re-embed everything:** send `{ "force": true }`.
- **After adding a new product** to the catalog, call the backfill
  again — new products are embedded, existing ones are skipped.

## Using it

```bash
curl -X POST https://shahjahanaibuy-b1zp.vercel.app/api/v1/visual-search \
  -H "Content-Type: application/json" \
  -d '{"imageUrl": "https://example.com/photo-of-a-laptop.jpg", "limit": 5}'
```

Or caption text only:

```bash
curl -X POST https://shahjahanaibuy-b1zp.vercel.app/api/v1/visual-search \
  -H "Content-Type: application/json" \
  -d '{"caption": "silver laptop with black keyboard", "limit": 5}'
```

Success response (200):

```json
{
  "success": true,
  "data": [
    {
      "id": "3aa8470f-...",
      "slug": "macbook-air-13",
      "name": "MacBook Air 13",
      "brand": "Apple",
      "similarity": 0.812,
      "lowestPriceUsd": 999
    }
  ],
  "meta": { "mode": "vector", "caption": "a silver laptop on a desk", "note": "..." }
}
```

- `similarity` is cosine similarity (1 = closest), computed by the
  database — never invented. `lowestPriceUsd` is the lowest recorded
  merchant price, or `null` when none exists.
- Each match links to `/products/[slug]` on the site.
- Honest empty state: if the catalog has no embeddings yet, the
  response is `200` with `[]` and a note saying the backfill is
  still needed.

## Honest limits

- The caption describes what BLIP sees; a wrong caption gives a
  wrong match. The route returns the caption in `meta` so the
  caller can see what was actually matched on.
- Embeddings are only as good as the catalog text (name + brand +
  description). Products with thin descriptions match less well.
- No photo is ever uploaded, stored, or embedded — only public
  image URLs (fetched server-side for captioning) or typed text.
- The free Hugging Face tier is rate-limited; the route is capped
  at 10 requests/minute per IP.

# CLIP Embeddings — Local, Zero API Calls

A **second, separate** embedding space for visual search, built
entirely offline on a developer machine — no API calls, no photos.

## Two embedding spaces (never mixed)

| Space | Dims | Table | RPC | Generated by |
|---|---|---|---|---|
| MiniLM (default) | 384 | `product_embeddings` | `match_products` | HF Inference API (backfill route) |
| CLIP | 512 | `product_clip_embeddings` | `match_clip_products` | Local script (below) |

CLIP text embeddings are **512-dimensional**; the MiniLM table is
`vector(384)`. The two spaces are not comparable: a 512-dim CLIP
vector must never be written into the 384-dim table, and a query is
matched only against its own space. The route consults the CLIP
table **first, when it has rows** (`meta.mode: "vector-clip"`);
otherwise it uses MiniLM (`meta.mode: "vector"`). Any CLIP-side
failure falls back to MiniLM — never an error, never a fake match.

## Why CLIP stays OUT of the serverless route

The CLIP text encoder alone is ~150–250 MB. A Vercel Hobby
function has a **10-second timeout** and a **250 MB function size
limit** — downloading and loading the model on a cold start would
exceed both. So the route never runs CLIP: it embeds only the
caption **text** via the Hugging Face Inference API
(feature-extraction, `openai/clip-vit-base-patch32`) and matches it
against the vectors this script stored. The heavy work happens once,
offline, on a developer machine.

Model used by the script (verified from the installed
`@huggingface/transformers` v4.3.2 package itself — its pipeline
registry defaults zero-shot-image-classification to this ID):
`Xenova/clip-vit-base-patch32`. Only the **text** encoder is loaded
(`CLIPTextModelWithProjection`, projected 512-dim `text_embeds`), so
the vision encoder is never downloaded.

## Owner setup (CLIP path)

### 1. Run the CLIP SQL (once)

In the Supabase dashboard → SQL Editor, open
`supabase/add-clip-embeddings.sql`, press **Ctrl+A**, then **Run**.
It creates `product_clip_embeddings` (one 512-dim vector per
product) and `match_clip_products(query_embedding, match_count)`.
Verify: the last result should list `product_id`, `embedding`,
`updated_at`. (The MiniLM SQL from the section above is independent
— run it too if you want the MiniLM fallback.)

### 2. Run the local embedding script (once, from your machine)

Prerequisites: the repo checked out, `npm install` done, Node 18+.

```bash
# 1. Validate setup without downloading the model:
SUPABASE_URL=https://<ref>.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=<service-role key> \
node scripts/embed-products-local.mjs --dry-run

# 2. Full pass (first run downloads the CLIP text encoder once,
#    ~150-250 MB, into ~/.cache/huggingface/hub; later runs reuse it):
SUPABASE_URL=https://<ref>.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=<service-role key> \
node scripts/embed-products-local.mjs

# 3. Useful flags:
#    --limit 3   embed at most 3 products (smoke test)
#    --force     re-embed everything, replacing stored vectors
```

- The service-role key comes from the Supabase dashboard
  (Project Settings → API). It is read from the local shell only
  and is **never printed or logged** by the script.
- The script embeds **product text only** (name + brand +
  description, the same shape as the MiniLM path). No photos are
  read, downloaded, or stored anywhere.
- **Resumable:** without `--force`, products that already have a
  CLIP embedding are skipped. After adding a new product, re-run
  the script — new products are embedded, existing ones skipped.
- Output is `{ total, alreadyEmbedded, embedded, failed }`;
  per-product failures are listed without failing the whole run.

### 3. Verify

```bash
curl -X POST https://shahjahanaibuy-b1zp.vercel.app/api/v1/visual-search \
  -H "Content-Type: application/json" \
  -d '{"caption": "silver laptop with black keyboard", "limit": 5}'
```

`meta.mode` should read `"vector-clip"` once the CLIP table has
rows. If it still reads `"vector"`, the CLIP table is empty or the
SQL/script step above is incomplete — the route falls back to
MiniLM and says so in `meta.note`.
